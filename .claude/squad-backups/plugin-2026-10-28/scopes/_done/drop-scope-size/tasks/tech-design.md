## Decisions (mine, inside the architecture)
| # | Decision | Why |
|---|---|---|
| D1 | **No shim in any release.** The engine in 0.6.0 reads only `team:`. `size:` in `scope.md`, `size`/`qa-b`/`qa-whitebox` in a `when:` are a compose and lint error naming the file or rule and pointing at `squad-process adopt` (converter, dry run first) or, for overlays, at `squad-process upgrade`. **Branch-internal scaffold (not a shim, never released):** tasks 01 to 09 merge into one integration branch with the old rule files still alive, so until task 10 `read_home` leaves its existing `size:` path as it is and, for such a home only, fills the duty facts from `legacy_team()` (the converter's mapping, D3). Task 10 deletes the path and its tests; the task 10 AC proves it is gone. **Manager FINAL (scaffold approved on conditions):** branch-internal only; deleted in task 10 with a test that it is gone; the sha the PO merges has no `size:` path, checked by the full suite `--tz` run (task 10 test stays in the suite). | Each task stays green and Developers work in parallel on disjoint files, without a half-built engine reaching a release |
| D2 | **New rules get a new prefix, old IDs stay.** New file `templates/squad/process/teams.md`, prefix `TEAM` (add `("TEAM", "teams")` to `FILE_ORDER` after `SIZE`). | D3 | `DUTIES` lives in `bin/squadrules.py`: `{fact: chain}`; chain items are role names or terminal values (`ticket`, `dev`, `manager`) plus the pseudo-item `qas` (`qa-white` or `qa-black` present, as tokens). `resolve_duties(team: frozenset) -> dict` is pure. | D7 | Pinned engine: `squad-spawn` and `squad-respawn` run `"$runtime/bin/squad-process" compose` in composed mode. **Pinned scope below 0.6.0 (Architect accepted, §1, §5, §7):** its `scope.md` keeps `size:`, so `squad-spawn` and `squad-respawn` run from the PO shell `exec $runtime/bin/squad-spawn` / `squad-respawn` with the same arguments (the pin's own gate, compose and prompts). If the runtime lacks the file, refuse with a warning (the running engine would reject `size:`); never fall back. Tested with a pinned fixture. | Fixes the pin-integrity hole (tech-t1-answer C) |

## Design per task (patterns, reuse; LC-10)
- 01: follow `squadrules._conditions`/`matches` style (regex, `ValueError` with the key and value). `read_home` keeps `_kv`, `_FACT_DEFAULT`, `_FACT_VALUES`; the team line is parsed like `size` (commentary: `team: a, b  (note)` strips a trailing `(`...`)`). Presence facts are `yes|no` strings (same type as `design`). `qa-black`, `design`, `architecture` derive from the team when `team:` is present; a home with only `size:` is the D1 scaffold (removed in 10), not a product path. Reuse `sr.matches` unchanged. `resolve_duties` is table-driven; never `if/elif` per duty.
- 02: `squad-process team --home D [--has ROLE]`: exit 0 and print the comma list (`none`/`undecided`); `--has` takes a role name and maps it by `ROLE_KEY`, exits 0/1. No `--from-size` (no brief hint, no second path; the converter dry run is the only size-to-team mapping). Errors go through `ComposeError` lines to stderr, exit 2 as `compose` does. Converter skips a pinned scope (its engine still reads `size:`) and says so in the dry run. Converter reuses `squadadopt.open_homes` and the dry-run print pattern of `format_plan`/`execute` and `squadio` for atomic writes.
- 03: `squad-spawn` calls `squad-process team --home "$home" --has <role>` once; gate message names the role and the file. Preserve the existing refusal order (before herdr call, worktree, label). The gate takes a role name and maps it by `ROLE_KEY`. Pinned scope below 0.6.0: hand off to the pin's `squad-spawn` (D7). `squad-log-message`: call team CLI only inside `third_return` (FAIL) and on any error use `Manager`.
- 04a/04b/05/06: mechanical retarget follows architecture section 3 exactly: **one rule per (duty, acting role)**; `when:` = at most one DUTIES/presence key + orthogonal `goal|qa|design|architecture|qa-black` (`qa-b` only in files not yet retargeted, gone at the cutover). Keep ID if the body is unchanged. A twin whose body is identical to a sibling collapses into one ID (the lowest letter); tombstone the others. Text that names "S", "M", "L" or "size" is rewritten with Team/Duty owner/Checker terms. Run `squad-process lint` and the grep of the files' tests before HANDIN (CLAUDE.md rule on `templates/` touches).
- 07: report keeps `or ""`; add a `team` string beside `size` (old scopes show their `size:` text as display only, no mapping); JS shows team initials or old size. Fixtures include one old-size scope and one team scope (AC 23).
- 08: reuse `load/choose` and `squad-respawn` composing; output lists roles whose rule IDs/bodies/duties differ; `--po-ok` required for designer/architect add; refuses remove outside an iteration boundary flag `--at-boundary`.

## LC-12 migration, compatibility, deploy plan (LC-13: written, not run)
Contract changes: `scope.md` (`size/design/architecture/qa-b` lines to `team:`, tokens `qa-white`/`qa-black`), rule `when:` language (`size`, `qa-b`, `qa-whitebox` removed; `qa-white`, `qa-black` added), composed header, `squad-spawn` gate, `squad-process` subcommands, report JSON (`scope.team` added, `size` kept as display for old scopes). **Breaking by decision (PO, E4): no read-side shim, no dual support.**
Additive first inside the branch: tasks 01 to 09 add (with the D1 scaffold so each merge is green); only task 10 removes the old language and the scaffold. No release carries both languages. Old `scope.md` files that stay on `size:` are pinned scopes only (they run their pinned runtime); the new engine does not read them, report and hook only display or degrade (Manager as notice target).
Deploy order (PO runs it): 1. close or finish open scopes if possible (squad-close scope merges first; its `templates/squad/process/` edits conflict with 04b/05/06, so rebase). 2. Merge this scope's integration branch (PO). 3. **Before any respawn of an unpinned squad under 0.6.0**: `squad-process adopt --dry-run`, confirm, `--apply` (writes `team:`, removes the four old lines, backup); until then the engine refuses to compose with a pointer to this step. Pinned scopes are skipped. 4. In each composed squad run `squad-process upgrade` and resolve the stale overlay ops (every op with `when: size`, `qa-b` or `qa-whitebox` is listed with its translation). 5. New scopes: `squad-start` proposes the team. Open pinned scopes keep running their pinned runtime.
Rollback: revert the merge commit; pinned scopes (including any started under 0.6.0) run their own `git archive` runtime, so they do not depend on the working tree; unpinned squads that ran the converter hold `team:` lines the old engine ignores, so restore their `scope.md` from the converter's backup (the dry run is mandatory, the backup follows the existing `_backup` pattern); overlays edited after `upgrade` need the same manual revert.
Post-deploy checks: `squad-process lint`; in a scratch squad `squad-start`, `squad-spawn qa-whitebox`, refusal of `squad-spawn architect` without it on the team, `squad-process compose` for a decided and an undecided team; compose on an unconverted `size:` scope.md exits 2 with the converter pointer; converter dry run and apply on a copy of `plugin-bk261023`; respawn of a pinned 0.5.2 fixture from the PO shell; `squad-report` on a folder holding one old and one new scope; `python3 tests/run_suite.py --tz` receipt on the integration sha.
