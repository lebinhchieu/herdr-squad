## 1. Rule-text size budget at ticket time and before HANDIN

**Make the ticket name the budget and the Developer test it before the first commit.** This is the second scope with the same cause; the cost grew from 1 return to 7.

```
- op: append
  rule: <ticket-writing rule, L = Team Lead>
  text: "A ticket that adds or lengthens rule text for a role names every team x flag combination whose composed size it changes, the limit that applies, and the current headroom in bytes (from `squad-process` composed output). A ticket in a wave whose tickets touch the same composition lists the shared headroom once and assigns it."
  upstream: proposed
- op: append
  rule: <Developer pre-HANDIN rule>
  text: "If your diff adds or lengthens rule text, run the size-budget test for every combination the ticket names before the first commit and again before HANDIN; over budget: ASK the Team Lead before building further."
```

**Evidence**

**Saving:** avoid about 5 of the 7 returns.
- dev-11 spent about 100 turns over the 56-80 turn norm, about 15M cached-input tokens at an assumed 150k mean ctx.
- Each return adds a QA whitebox and blackbox pass, about 1M.
- Order of 5-10M per scope.

## 2. Second `fresh` event on one ticket: stop and hand back

**After a respawn, a second fresh-start message means stop, not respawn again.** The rule today is silent on the second hit.

```
- op: append
  rule: COST-5
  text: "A second fresh-start message on the same ticket: do not respawn again. Write the notes, send the Team Lead `BLOCKED <TASK-ID>: context cap twice` with what is left, and stop; the Team Lead splits the rest into a new ticket."
  upstream: proposed
```

**Evidence**
- `usage-events.jsonl`: dev-11 at `2026-10-27T17:02:02.458Z` (session 9f2d5b02), again at `2026-10-27T17:17:58.753Z` (session 9475ac1c).
- Action text: "if you are mid-ticket, run once: squad-respawn". The second session hit the line again.
- Row `plugin-dev-dsz-11`: peak 301k, last 161k, 3 returns.
- Contrast: `plugin-dev-dsz-12` (event `2026-10-27T17:59:42.408Z`, peak 206k) then `-12b` (56 turns, peak 90k). One respawn worked there.

**Saving:** about 4M cached-input tokens (range 3-5M).
- About 40 turns above the line at a mean 200k ctx, against a 100k fresh session.
- One extra ticket handoff costs about 30-40k.

**Check printed text, tables and alternatives against the spec by script, and put the result in the HANDIN.** `CLAUDE.md` already requires goldens for touched text; that does not cover a table matching no golden.

```
- op: append

  text: "When the spec or AC gives exact output lines, tables or alternatives, diff your output against them line by line (a script, not by eye) and put the result in the HANDIN. Every AC line of that kind has one check."

```

**Evidence**

**Saving:** about 2-4M if both returns are prevented.
- `-12b`'s 56 turns at about 60k mean ctx, about 3M, plus the QA recheck, about 1M.
- Count only half: the 12b respawn was also a context-cap effect.

## Plugin proposals

**Four findings in the usage tooling; items 1-3 repeat scope A's.**

1. **`usage-events.jsonl` has no `ctx` or turn count** (A plugin item 1). Proposals 2 and 4 cannot be sized: the 39 events (`2026-10-27T12:34:55.028Z` to `2026-10-27T18:43:22.232Z`) say a rule fired, not at what size. Add `ctx` and `turns` to each event.
2. **`squad-usage` hides earlier sessions** (A plugin item 2). `plugin-tech-drop-scope-size` has 10 `fresh` events, `plugin-qaw` and `plugin-qab` 7 each, yet rows show peak = last (66k / 42k / 45k). `plugin-dev-dsz-11` shows peak 301k above last 161k with 0 compactions, so the peak's sessions are unclear. One row per session, or max peak plus session count.
3. **`fresh` event does not record the path taken** (A plugin item 3). dev-11 has two events 15 min apart; the log cannot say whether the first was a respawn or a retire. Record `respawned`, `retired` or `ignored`.
4. **No `fresh` event for the Manager at 148k.** Row `plugin-mgr-drop-scope-size`: peak 148k, 157 turns, 1 cache expiry; no event line for it. Either the hook skips the Manager or the line is not enforced for it. State in the Manager card whether COST-3 binds the Manager, and what it does before an idle wait over 1h. The expiry cost one full uncached re-read of about 148k.
