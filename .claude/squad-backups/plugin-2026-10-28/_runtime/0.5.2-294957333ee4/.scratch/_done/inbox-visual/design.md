# Inbox visual: technical design (Tech Lead)

Status: ready (spec `spec.md` V-01..V-30 AGREED; tickets `issues/01..07`; plan `plan.md`)

**Add one pure parser (`markup.ts`) and a few pure helpers to `core.ts`, then redraw the item screen, list, band and done list in `ui.tsx` from them, using only theme keys and text weight. No CLI, contract, `actions.ts` answer path or `agents/manager.md` change.** The mod stays "everything is Text/Box/Button; every string through `sanitize`".

## Decisions

| # | Decision | Why |
|---|---|---|
| T1 | **Own parser, no library.** `hooks/po-inbox/markup.ts`: `parseBody(text): Block[]`, `parseInline(line): Span[]`, `plainOf(blocks): string`. Pure, no `$`. | The mod's module environment has no Node and no npm; the subset (V-05) is about 150 lines; a library would be an irreversible new dependency for no gain. Not an ADR: a feature note here. |
| T2 | **Order of work on a body:** `sanitize` → `<br>` to `\n` → drop the first line if it equals the title (as today) → `parseBody`; this pipeline is one pure function in `markup.ts` (`bodyBlocks(body, title)`), not inline in `ui.tsx` (QAW 1.7). Parsed text is only ever drawn as `Text` children, never evaluated. | V-27: the sanitiser stays the one gate; the parser adds no control characters. |
| T3 | **Parser is linear and total.** Line by line, `indexOf` scans, no backtracking regex on user text. An unmatched `**` or backtick scans once, then the rest of the line is plain (no rescan per opener). No input throws; anything not matched is a plain paragraph line. | V-28 (10,000 chars on one line, 5,000 `**`, unclosed fence, only `\|`): open within 2 s. |
| T4 | **Never drop, by construction and by test.** Each element drops only its own syntax characters. `plainOf(parseBody(x))` words equal the words of `x` minus those characters; a test checks it on every fixture and on a seeded random generator. | V-07. |
| T5 | **Block set:** `heading{level,spans}`, `bullet{depth,spans}`, `number{n,depth,spans}`, `code{lines}` (fence to fence, or to the end if unclosed), `table{header,rows}` (header row + separator row `\|---\|` + 0..n rows; anything else is paragraphs), `rec{spans}` (line whose first non-space text is exactly `[rec]` followed by space or end), `para{spans}`, `blank`. Inline: `**x**` bold (closed on the same line, non-empty, no `**` inside), `` `x` `` code (closed, non-empty). Italic, links, images, quotes, HTML: plain. `#1`, `2024-10-16`, `1.5`, `-5`, `-x` (no space) plain: markers need their space. | V-05, V-06. |
| T6 | **Colour is a theme key, never RGB:** green `success`, red `error`, amber `warning`, dim = `dimColor`. Constant `TONE` in `core.ts`. Structure uses `bold`/`weight`, `italic`, `underline`, `inverse`, `strikethrough`, Box `borderStyle`/`backgroundColor` with a non-meaning theme key; never `success`/`error`/`warning`/`suggestion`. `suggestion` leaves the band. | V-15, V-18; follows the user's theme (light and dark). |
| T7 | **Recommended option is a pure function** `recommendedKey(rec, options): string \| null` in `core.ts`, built to the V-11 table row by row (leading run only: `^\s*\(([a-z])\)`; refuse when the text right after it is `+`, `/`, `,\s*\(x\)`, or `and`/`or` `\(x\)`; key must exist in `options`). The spec table wins over any other parser. | V-11, V-12: "when in doubt, mark nothing". |
| T8 | **Width is cells, not code units:** `cellWidth(s)` (East Asian wide and emoji = 2, combining = 0, else 1) and `rowsFor(text, cols)` (rows a wrapped text takes) in `core.ts`. `tableLayout(table, cols)` returns `aligned` (column widths, only when `cols >= 60` and the table fits) or `stacked` (each row `column: value`, wrapped). | V-08 (CJK/emoji cells), V-22. `String.length` would clip. |
| T9 | **v3 (spec V-01/V-02 after QAB's baseline: the pane is ~1/3 of the terminal, 6 content rows at 24 (read live by QAW 2026-10-16: scroll.bodyRows is 6 at 24 rows, 11 at 40; the first count of 7 was a miscount); the engine caps an inline pane at half the terminal and `$.ui.open({rows})` is only a request, so the mod cannot raise it).** The item screen is one column in V-03 order that the PO scrolls with the engine's own keys. The first viewport is the **top block**: back button, kind + blocks, title (capped at `titleCap` rows, see below), then one row `recPointer(rec, options)` ("recommends (c)" when `recommendedKey` marks one, else the start of the rec through `clipCells`). The pointer is never the only copy of the rec (V-12). **The body is cut by rendered rows:** `bodyBudget = max(floor, scroll.bodyRows - chromeRows)`, `chromeRows` = `rowsFor` of everything that is not body, `floor` is the Designer's number (default 3), so options and controls come after a short preview and `Show all` draws the rest; where everything fits, everything shows. Blocks are kept whole while they fit. "… N more lines" counts source lines left. Replaces `ANSWER_FIRST_LINES = 12`. A hint that more is below is the Designer's (V-01). | V-01, V-02, V-09, V-12. A fixed 12 lines cannot hold; "all fits at 24 rows" is impossible by measurement. |
| T10 | **List cap:** `capGroup(items, expanded): { shown, hidden }` (7, V-20); `InboxUi` gets `more: string[]` (group keys opened); `FRESH_UI` and `goTo` reset it. Hotkeys 1-9 keep numbering over the shown rows, in order. | V-20: `+N more` expands in place; heading and band counts stay totals. |
| T11 | **The PO's own text is drawn plain:** the answer shown back (`it.answer.text`), the unsent draft and the note are never parsed (V-26). `submitAnswer`, `describePrompt` and the CLI call are untouched: the diff of `actions.ts` outside `FRESH_UI`/`goTo` is empty. | V-26. |
| T12 | **Real samples, not invented ones (process.md "Verify against the real thing").** Fixtures dir: `hooks/po-inbox/fixtures/visual.ts` (a code-named file like the contract fixtures, imported directly; `fixtures/index.ts` is generated and untouched): E1 and E2 verbatim from `scopes/inbox-visual/inbox.jsonl` (they move to `_done/` at close, so they are copied, not linked), plus one real body per squad escalation file under `.claude/squads/*/scopes/_done/*/escalations.md` that holds a table, the constant case (one-line body equal to the title, empty body), and QA blackbox's hostile list (`evidence/qa-b-spec-review.md` → Fixtures; the 10,000-char line and 5,000 `**` are built in code, not stored). ## What the mod API gives the Designer (checked in `claude-code.d.ts`)
- `Text`: `color` (theme key or raw), `backgroundColor`, `dimColor`, `bold`/`weight`, `italic`, `underline`, `strikethrough`, `inverse`, `wrap` (`wrap|truncate|...`). `size`, `mono`, `tabular` are ignored on the terminal. Terminal text is always monospaced.
- `Box`: `flexDirection`, `gap`, `padding*`, `margin*`, `width`, `borderStyle`, `borderColor`, `backgroundColor`, `flexWrap`. A border costs 2 rows and 2 columns: at 40 columns options should not use one.
- Theme keys: `success`, `error`, `warning` (the three meanings), `inactive`/`subtle` (quiet), `suggestion`, `permission`, `claude` (accents: not allowed for meaning), `text`, `inverseText`.
- Width is `e.props.bodyColumns`; height is `e.props.scroll.bodyRows`; compact is `bodyColumns < 60`. No other measurement exists, which is why T8 and T9 estimate.
- `Button`: `plain`, `variant`, `hotkey`, `label`; `Select` and `Input` as today. A Button's colour is the engine's: the Designer confirms `variant="primary"` takes none of green, red or amber (V-15); if it does, the Send button goes plain.
- `Show all` and `+N more` are Buttons with `patchUi` handlers (state is the atom `ui`).

## Technical AC common to every ticket
1. `claude plugin validate <repo>` clean; `claude plugin test <repo>` green; suite per `CLAUDE.md` → Running tests, receipt on the final sha.
2. Every drawn string of a new element goes through `sanitize`/`line` before it is drawn; one test per element class with ESC, an OSC sequence and U+202E in its source text (V-27).
3. No `$.prompt.*`, `$.fs.*` or new `$.process.run` argv appears in the diff (`claude plugin validate` lists mod calls: unchanged).
4. New tests live in new `*.test.ts` files named by the ticket; an existing test in `ui.test.ts` is edited only where the new look makes its assertion wrong, and the ticket says so in `dev-evidence.md`.
5. No new dependency; no change to `bin/`, `agents/`, `skills/`, `tests/*.py` (except where a ticket names one).
6. (QAW) Every test file a ticket adds runs 5 times in a row, whole files, result in `dev-evidence.md`; timing assertions use generous bounds, never `sleep`.
7. (QAW) Colour allow-list: in the drawn tree of every state the ticket draws, every `color`/`backgroundColor`/`borderColor` is a theme key, and `success`/`error`/`warning` sit only on V-15 elements.
8. (QAW) QA whitebox mutates one branch per ticket (drop a table cell, drop the `+` refusal in `recommendedKey`, cap at 8, trim the answer text); each must turn a test red, else FAIL "weak test".

## Compatibility, migration, deploy
Additive and display-only. Stored data, the `list --json` contract (version 1), `escalations.md` and every CLI command are unchanged. Roll back by reverting the commits; nothing persists. Deploy: the PO merges and bumps the plugin version (the integration ticket bumps `plugin.json` minor); no order across repos. The mod reloads at the next session.

## Known limits (accepted)
- Width counting is a table of ranges, not full Unicode (grapheme clusters with ZWJ may be off by a cell); a wrong estimate costs a row of cut, never a dropped word, because Show all draws the whole body.
- The pane height is the host's (about one third of the terminal inline, half at most; dock from 110 columns is taller): the mod asks `rows: 18` today and gets 6 at 24 rows. V-01 therefore bars only the top block (kind, blocks, title, rec pointer) in the first viewport.
- The mod cannot measure a real terminal's wrap: `rowsFor` is an estimate; the V-01 bar is checked in a real herdr pane by QA blackbox at 80x24 and 40x24.
- Markdown beyond V-05 stays plain by decision D5.

**T9 v3.2 (Tech Lead ruling 2026-10-16, after QAW's live read of `scroll.bodyRows` = 6 at 24 rows, 11 at 40):** the top block must fit `scroll.bodyRows` as the host hands it, never a constant 7. `titleCap = clamp(bodyRows - 1 (back) - headerRows - pointerRows, 1, 3)`: at 80x24 (header 1 row) the cap is 3, at 40x24 (header 2 rows) it is 2; a cut title keeps the `… full title` row of the design, so no word is lost. The pointer row is never dropped for the title. Tests derive the cap from the rule at the real `bodyRows` (6 and 11), not from 7.
