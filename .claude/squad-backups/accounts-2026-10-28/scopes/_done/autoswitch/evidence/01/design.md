### Finding that shapes the rule
`cswitch` already waits for the pane to finish its turn (`herdr agent wait`, no `--until` = idle|done|blocked) before `/exit`. A pane **working** at tick time finishes that turn, then is restarted: in-flight work is not lost. So herdr `working` says "busy now", not "has work after the restart". Work that survives a restart: (a) a turn cut off (pane `blocked` at a dialog when `/exit` is typed, or an unanswered last record); (b) a message sent to the agent and never answered; (c) a **message the agent SENT that failed** because the recipient was down (`not reachable`): the pending work belongs to the *sender*. (c) is the real loss in the 2026-10-22 batch; `squad-log-message` logs successes only, so `messages.jsonl` never sees it.

### Signals compared (T2)
| Signal | Cost | Misses / false hits | Verdict |
|---|---|---|---|
| herdr `agent_status` (`agent list`, 1 call/tick) | free | `working` finishes before restart (false hit); idle sender with a failed send looks idle (miss) | `blocked` counts as pending (cut off by `/exit`); `working` ignored |
| `messages.jsonl` row `to == name` newer than last turn | one file per pane, found from pane env `SCOPE_DIR`, else `GOAL_DIR`, else `SQUAD_DIR` (same order as `bin/squad-log-message`) | a delivered message starts a turn at once, so "newer than last turn" is rare (race); failed sends never logged | secondary, kept |

| **session transcript tail** (`~/.claude*/projects/<cwd-slug>/<session>.jsonl`; session id = `agent_session.value`, already read by `cswitch`) | tail ~200 lines of one file | error shape of a failed SendMessage unverified (no real sample on disk: grep of `~/.claude-2` transcripts found none) | **chosen**, plus `blocked` and the messages row |

### The rule (T1, T4)
`pending(agent)` is true when ANY of, read from the agent's transcript (records carry `timestamp`; **last-turn time = timestamp of the last `assistant` record with `stop_reason: end_turn`**; real shapes: idle mgr tail ends `21:44:55.996Z end_turn`, working dev tail ends `tool_use`):
1. **Cut off**: last `assistant` record has `stop_reason: tool_use`, or a `user` record follows the last `end_turn`; OR herdr `agent_status == blocked` at sample time.
2. **Failed send**: since `T0` a `tool_result` of a `SendMessage` call has `is_error: true` (text `not reachable` expected, unverified) and no later successful `SendMessage` to the same `to`.
3. **Unanswered message**: `messages.jsonl` has a row `to == name` with `ts` after the last `end_turn`.
`T0` = first `-> account` line of this batch in `cswitch.log` for the workspace.
Sampling, **twice** (D1 fix): clauses 1 and 3 are sampled **inside `cswitch`'s detached block, right after `herdr agent wait` returns and before `/exit`** (via `cwake --mark <pane>`; skipped when `CSWITCH_WAKE=off`). At that moment the pane is idle/done, so a `tool_use` tail is a real cut-off, not a pane that was merely mid-turn when the tick started (a working pane finishes its turn first, so it is NOT marked; a `blocked` pane is not waited on after the `--until` fix, it is marked at once and skipped for `/exit` until idle). The result is written to `wake-pending/<pane>` = `epoch name reason`. Clause 2 is sampled in `cautoswitch` after the batch ( failures happen in other panes' down windows, after the sender was sampled; the transcript survives `--resume`). Woken if either sample marked it. Fail direction: transcript, `messages.jsonl` or herdr unreadable/missing → not pending + one log line naming the file; never wake-all.

### Transcript key paths (F1)
Real nesting, as in the live transcripts (the `.derived` fixtures keep it): record type `.type` (`user`|`assistant`); time `.timestamp`; stop reason `.message.stop_reason` (`end_turn`|`tool_use`), never top level; a SendMessage call is an `assistant` record with `.message.content[]` item `{type:"tool_use", name:"SendMessage", id, input:{to,...}}`; its result is a later `user` record with `.message.content[]` item `{type:"tool_result", tool_use_id, is_error, content}` matched to the call by `tool_use_id`. `messages.jsonl` rows: `.ts`, `.from`, `.to`, `.type`, `.task`.

### Where the wake happens (T6, T7, T10)
`cautoswitch`, after the tick's per-pane loop, per workspace, once no pane of that workspace is *in flight* (waking one by one lets the first woken agent message peers that are down; reuse of the old wake plan). `cswitch` never wakes. Every off-default squad pane still moves (E1). **Order inside one tick (F2 fix):** (1) per-pane loop: every off-default pane is moved or retried, serially, each waiting for its `done`/`FAILED` line or the 900 s deadline (existing code); (2) only then the wake step, which sees each pane in one of three states: *back* (`done`, on target), *failed-again* (`FAILED` line from this tick's retry), *still-running* (900 s deadline hit, no `done`/`FAILED`). The wake step wakes every marked *back* pane of the workspace and never waits for the other two: they keep their marker and are not woken this tick. The retry itself is therefore inside the loop and cannot be "in flight" at the wake step in a way that delays it; a still-running pane is retried only after its 15-min `pending()` lapses. **Bound (D2 fix):** a pane is in flight only while `pending(pane)` is true (its `-> account` line is younger than 15 min and no `done`/`FAILED` yet). A pane that logged `FAILED`, or is still off-default after 15 min, no longer blocks the workspace: the other marked panes are woken in that tick (so the worst wait is 15 min, not 30). The stuck pane gets no wake; its marker stays and the next tick re-tries the move, and wakes it only if it comes back within the 30 min expiry. Idempotence: `cwake` deletes `wake-pending/<pane>` and appends `<ts> <pane> <name> wake sent|skipped` to `cswitch.log`; `pending()` (15-min "cswitch in flight") is untouched: it guards the *move*, the marker guards the *wake*. Marker older than 30 min: deleted with a log line, never sent. Never-marked pane is never woken, so nothing repeats each tick.
`cwake <pane> [--text T]`: `herdr agent wait <pane> --until idle --timeout 60000`; idle → `herdr agent prompt <pane> "$text"`; else log `WAKE SKIPPED <pane> state=<s>`, exit 1, marker removed (no retry loop). Skipped: pane whose claude env has no `SQUAD_NAME` (a person's own pane); pane not in `agent list` / no live claude (retired).

### Wake text (T8)
> Your Claude account changed (<old> -> <new>) and this session was resumed. A message sent to you or by you in the last minutes may have failed ("not reachable"). Resend what failed and carry on; if nothing is pending, answer with one line.

No paths, no tokens; `<old>/<new>` are account numbers. Override: `CSWITCH_WAKE_TEXT`.

### Failure modes / rollback (T9)
Idle gate and 60 s skip above. Rollback: `CSWITCH_WAKE=off` in the `cautoswitch` tab = today's behaviour exactly (move all, sample nothing, no marker, wake nothing). Values `on` (default), `off`. Existing bug for 02: `cswitch`'s `agent wait` without `--until` also returns on `blocked`, so `/exit` can land in a permission dialog; use `--until idle --until done` (then a blocked pane is waited on, not cut off).
