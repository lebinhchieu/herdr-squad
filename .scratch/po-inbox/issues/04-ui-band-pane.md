## Added after QA whitebox FAIL (90f8eb8); TL rulings, bind and replace where they conflict
- **AC5 heredoc (QAW F1, F2): the collapse is only for provably inert text.** (1) The heredoc operator is found on shell words, outside quotes (tokenise first): `--title "a <<E"` is a quoted argument, not a heredoc, and a following line keeps the full row in all three hooks. (2) Collapse a heredoc only when its delimiter is **quoted** (`<<'EOF'`, `<<"EOF"`, `<<\EOF`): bash does not expand such a body. An unquoted delimiter (`<<EOF`) keeps the full row, whatever the body holds (bash would run `$(…)`/backticks in it). The Manager's rule in `agents/manager.md` uses the quoted form, so the normal case still collapses. Tests: each of the above, in `ToolUse`, `ToolGroup` and `ToolResult`.
- **AC5 binary (QAW F3):** the first word is pinned: only `squad-inbox`, `./bin/squad-inbox` or an absolute path whose last segment is `squad-inbox` collapse. `git add --title x`, `/bin/ls add`, `/tmp/squad-inbox/evil add --title x` keep the full row; tests.

## Added after QA whitebox round 2 (e421b47, mixed-quote delimiter); TL ruling, replaces the heredoc rule above
- **Allow-list, not a shell parser.** The heredoc collapses only when the operator is exactly `<<'WORD'` or `<<"WORD"` with `WORD` matching `^[A-Za-z_][A-Za-z0-9_]*$`, the closing quote is followed by whitespace or the end of the line, and a later line equals `WORD` exactly (nothing else after it). The `<<\EOF` form is dropped (it keeps the full row). Anything else with `<<` (mixed quoting like `<<"reboot"F`, `<<-`, an unquoted word, an unterminated heredoc, a second heredoc) keeps the full row. Tests: each of these keep the full row in `ToolUse`, `ToolGroup` and `ToolResult`; `<<'EOF'` and `<<"EOF"` collapse.
