Gap found: ADR 0009 removed the board, so no per-agent status stream (working / waiting) is recorded any more. Time buckets must be derived from transcripts + messages.

Q1 · Time buckets: derive after the fact, no new recording

Derive from transcript timestamps + messages.jsonl, no new hooks. Proposed buckets per agent (and per task where attributable):

BucketRule
workingturn gaps ≤ threshold where the model or a tool is running
waitingtime inside a long tool call: background shell, Monitor, foreground test/suite run
blockingagent idle between a BLOCKED/ASK it sent and the matching reply
idleany other gap (agent parked, waiting for the PO or the Manager)
➡️ Yes: derive post-hoc with these four buckets; accept that boundaries are approximate and labelled "derived".

Q2 · Cost = estimated dollars at list price, reusing squad-usage

Reuse the existing cost-weighted unit (input, cache read, cache write 5m/1h, output, per model) from bin/squad-usage. Show tokens split by those four kinds plus the estimated $. Label it "estimated, list price" since the plan is not pay-per-token.

➡️ Yes: reuse squad-usage's parsing and price table; one source of truth for cost.

Q3 · Outputs: per-scope folder, canonical JSON + CSV tables, one self-contained HTML

<scope home>/report/data.json (canonical, schema-versioned: scope, tasks, agents, roles, intervals, returns) + one .csv per table (ready for pandas / DuckDB / a sheet) + report.html with data and the plugin's css/js inlined. A goal or any list of scopes gets a rollup built from the scopes' data.json files, not from the raw transcripts again.

➡️ Yes: JSON canonical + CSV, inline-asset HTML, rollups read data.json only.

Q4 · Zero LLM tokens to generate

The skill only runs one command (e.g. squad-report <scope|goal|--all>) and prints the output path plus a 5-line summary. Claude never reads the data to build the report. Narrative or recommendations only if you ask afterwards.

➡️ Yes: script-only generation; the skill body stays a few lines.

Q5 · Coverage: per-scope squads only, open and done scopes

Works on scopes/<s> and scopes/_done/<s>, and a goal = its scopes. Legacy flat squads (roster.md at the squad top, no scopes/) are not supported, same rule as squad-start. A scope still running gets a report marked "partial".

➡️ Yes: per-scope layout only; running scopes allowed, flagged partial.

Q6 · When it runs: on demand now, auto-at-close later

/squad:squad-report by hand. Hooking it into squad-close is a separate, later change so this stays one new skill + scripts.

➡️ Yes: on demand only for v1.
