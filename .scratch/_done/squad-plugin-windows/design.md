# Design: the plugin runs on native Windows (Tech Lead, scope win-compat)

**Verdict:** there are three Windows bugs, not two. The first one hit is the PO's inbox crash: `bin/squadinbox.py:8` does `import fcntl`, and Windows has no `fcntl`. Fixes: a Windows lock, explicit UTF-8 and LF everywhere in `bin/`, `squad-start` runs `squad-spawn` through a resolved `bash`. No change to the inbox mod. Per-site `encoding=` plus one guard test; one tiny shared `squadio.py` for the stdio setup only.

## Decisions

| # | Decision | Why |
|---|---|---|
| D1 | **stdio: reconfigure, not bytes.** New `bin/squadio.py` with `utf8_stdio()`: `stdin.reconfigure(encoding="utf-8", errors="replace")`; stdout and stderr also get `newline="\n"`. Every Python CLI calls it first thing in `main`: `squad-inbox`, `-label`, `-migrate`, `-notify`, `-process`, `-start`, `-usage`, `processlint.py`. | A pipe on Windows is cp1252, so `print("→")` or an emoji raises. `newline="\n"` matters as much: Windows text stdout writes `\r\n`, and bash `$(squad-usage --get ..)` keeps the `\r` on the last field, which breaks `${row%%$'\t'*}` parsing. Needs no PYTHONUTF8 from the caller. |
| D2 | **Per-site `encoding=`, no wrapper.** Reads: `encoding="utf-8"`; add `errors="replace"` for files we only parse or display and for subprocess output; **strict** for a file we read, edit and write back (`scope.md`, `roster.md`, `process.md`): a loud failure beats writing U+FFFD into it. Writes: `open(p, "w", encoding="utf-8", newline="\n")` or `write_bytes`; never `Path.write_text(newline=)`, which needs Python 3.10 and would be a new `TypeError` on macOS system python 3.9. The README's floor stays `python3`. Binary opens stay. | Idiomatic, greppable, about 45 sites. A wrapper would add an abstraction for one kwarg. One guard test (T3) keeps new code honest. |
| D3 | **Inbox lock.** `squadinbox.py`: `try: import fcntl except ImportError: fcntl = None`; with no fcntl use `msvcrt.locking(fd, LK_LOCK, 1)` on byte 0 of `inbox.jsonl.lock` (seek 0 first; `LK_UNLCK` before close). `LK_LOCK` gives up after about 10 s: raise `Refused("the inbox is locked by another squad-inbox", 1)`. Linux keeps `flock` unchanged. Both `os.open` calls (`append_events`, `locked`) add `getattr(os, "O_BINARY", 0)`: a Windows fd defaults to text mode and `os.write` would turn `\n` into `\r\n` in `inbox.jsonl`. | Same no-lost-row guarantee as Linux. A lock-file with O_EXCL leaves stale locks after a crash. |
| D4 | **stdin on Windows.** `select.select` on a pipe raises there. `stdin_text(only_if_ready=True)` returns `""` when the module constant `IS_WINDOWS` (`os.name == "nt"`, patched by tests) is true, instead of calling `select`: `only_if_ready` is true only when `--note/--text` was given, so the text is already there and reading a pipe nobody closed would hang. With no note (the pane's `answer --source pane`, text on stdin, `actions.ts:172`) `only_if_ready` is false and stdin is read on Windows too. The "both given" refusal is then not enforced on Windows; accepted. | Today the `except OSError` would swallow the error and silently return `""` anyway; make it deliberate. |
| D5 | **Launcher: always through bash, one code path.** `squad-start` runs `[bash, <squad-spawn as_posix>, ...]` at both sites, with `SQUAD_DIR` passed as `squad.as_posix()` (`C:/Users/x/...` works in MSYS bash, `C:\Users\x` does not reliably). Resolve `bash` once with `pick_bash(which, exists, nt, system_root)` (pure, injected). `which("bash")` first; on nt reject a hit under `%SystemRoot%\System32` or any `WindowsApps` folder (the WSL launcher and the Store stub: wrong bash). Fallback: from `which("git")` walk up at most 3 parents and take the first `<root>\bin\bash.exe` that exists. This covers `<Git>\cmd\git.exe` (the usual PATH entry), `<Git>\bin\git.exe` and `<Git>\mingw64\bin\git.exe`; tests name all three. Missing: one line naming Git for Windows, exit non-zero, before any file is written. The `would run:` dry-run line is unchanged and needs no bash. | The issue's preferred fix. Always-bash needs no `os.name` branch, so Linux tests exercise the real path. |
| D6 | **Inbox mod (`hooks/po-inbox/actions.ts`): no change, no T5.** It runs `bin/squad-inbox` by argv. The PO's error text `squad-inbox list failed: Traceback…` is the mod's `failure(r)` of the process output, so Python started: the host resolves the shebang. If, after T2a, the PO checklist still shows a spawn error (not a traceback), T5 becomes `['python3', path, ...]` plus a test that pins the argv. | Evidence over speculation. |
| D7 | **`python3` stays.** `squad-spawn:163` and `squad-close:85` call `python3`; the reporter's run passed line 163. `squad-close`'s inline snippet becomes `python3 -X utf8 -c` (it reads JSON from stdin and prints). Checklist step 0: `python3 --version` in Git Bash. | A Store or python.org install may only have `python`; that is a prerequisite check, not a code change. |
| D8 | **`jq` is a prerequisite** (the README lists it). `squad-respawn`, `squad-retire` and `squad-log-message` check `command -v jq` first. The first two fail with one line naming `jq` (Git for Windows does not ship it; `winget install jqlang.jq`). The hook `squad-log-message` logs nothing, prints one stderr line and exits 0. Answers BA O2: no rewrite. | A jq-free rewrite of three scripts is a bigger change than the bug. |
| D9 | **`squad-notify`**: it reads `/proc` and `/dev/pts`, so on Windows it finds no client and does nothing. Keep; test only that it exits 0 with no output when `/proc` is missing. | Best-effort toast, no feature loss that was ever there. |
| D10 | **Not fixed, stays on the checklist:** `os.replace` over a file another Python process holds open raises `PermissionError` on Windows (`squadinbox.atomic_write`, `squadlabel`, `squadprocess`, `squad-migrate`). The inbox answer-cell write is already a warning and `list` fills it later. | Cannot be tested here; a retry loop for a race we have not seen is speculation. |
| D11 | **`.gitattributes`**: `* text=auto eol=lf` plus `bin/* text eol=lf`. | The extensionless scripts are the ones that must never become CRLF; `text=auto` guesses. The index is already LF, so no renormalise commit. |
| D12 | **`squad-usage` on Windows: quiet no-op.** Transcripts are read `encoding="utf-8", errors="replace"`. The Stop hook passes `--transcript`, so `--check` works wherever Claude Code gives a path; the fallback lookup (`projects_glob`, base from cwd) is Linux-shaped and may find nothing. `--check` with nothing found: exit 0, no output, no traceback. | E3 asks only "must not crash"; cost rules are advisory. |

## Test method (every ticket)

- **Simulated Windows locale:** run the CLI with `PYTHONUTF8=0 LC_ALL=C PYTHONIOENCODING=cp1252` (QAW: ASCII is stricter than cp1252 on read, and cp1252 mojibakes instead of raising, so also compare the **bytes** written to the expected UTF-8 bytes).
- **Simulated Windows stdout:** wrap `sys.stdout` in a `TextIOWrapper(BytesIO, encoding="cp1252", newline="\r\n")`, call `utf8_stdio()`, print `→ 🦀`, assert the bytes are UTF-8 with `\n`.
- **No fcntl:** `sys.modules['fcntl'] = None`, plus a fake `msvcrt` module backed by `fcntl.flock` for the concurrent-writers test.
- **LF:** `od -c` or `read_bytes()` on the written file, never read it back through the same code.

## Order

T0 `squadio.py` (first, tiny) → T2a, T1, T2b in parallel → T2c → T3 (guard test + `.gitattributes`, blocked by all code tickets) → T4 integration. Real Windows only on the PO's checklist.
