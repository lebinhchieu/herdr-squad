# Technical AC 25: Panels menu and Columns popover open under their button (Tech Lead: board-tl-dashboard)
Rewritten 2026-11-04 to follow `ui-design/design-v7.md` §3 (final). Common AC: TC.1, TC.3, TC.6, TC.10-TC.12; UI-COMMON TU.1, TU.3, TU.4, TU.9. Binding with the BA's `tasks/issues/25-*.md` (T25.AC1-AC6; AC5 covers the Columns popover).

## Design notes
- Cause (read): `.pop` is `position:absolute;right:var(--gutter)` with no `top`, appended as the last child of `#app`, so it sits at the page bottom. The Columns popover `.cpop` is `position:fixed` and is placed only on `resize` (`placeColumns`), so it does not follow the button on scroll.
- v7 rule for BOTH (one component, one rule): the button and its popover share one `position:relative` wrapper. The popover is `position:absolute; top:100%; left:0; margin-top:4px`. It scrolls with the page by itself, so no scroll listener is needed. On open, on `resize` and on a text-size change it measures once: if its right edge passes `innerWidth - 8`, shift left by the overflow (`margin-left` negative); set `max-height = innerHeight - buttonBottom - 12` and `overflow:auto` for the list (the Columns footer stays visible: list scrolls, footer does not). **It never flips above** (v7; my earlier "open above" is dropped).
- One shared pure function `BOARD.popPlace(btnRect, popWidth, viewport)` -> `{shift, maxHeight}` (no DOM). `togglePop` and `openColumns` both call it; `placeColumns` is deleted or becomes the caller. Reuse, do not write two.
- Keep `aria-expanded`, `role=menu` / `dialog`, focus return to the button on close, Esc, outside click, second click. Closed label `Panels ▾`; with hidden panels `Panels (2 hidden) ▾`; open caret `▴` (v7 §3). Content text per v7 §3.
- Files: `templates/board/board.js`, `templates/board/board.css` only. 26 edits the same two files after 25 (same Dev, 25 first). Header markup: the Panels button gets a wrapper; the Columns button in each panel header gets one too. Tests that select the header by structure may need the wrapper: list each edited test in HANDIN.

## Technical AC
- **T25.TA1 Pure place function.** `popPlace` touches no DOM/window. One test, cases: fits; overflows right (shift = overflow + 8 margin); button near the bottom (max-height = vh - bottom - 12, never < 0); tiny viewport.
- **T25.TA2 Under the button, scrolled.** Headless Chrome at Small/Normal/Extra large, windows 1000 and 1440 px: popover top within 4 px of the button bottom and left edge within 2 px of the button left (or shifted only as far as the 8 px margin needs). Page scrolled 600 px: still within 4 px (T25.AC2). Run for the Panels menu and for the Tasks Columns popover.
- **T25.TA3 Inside the window.** At 1000 px, Extra large: the whole popover is inside the window (8 px margin); when taller than the room, the list scrolls inside and the Columns footer (Close, Reset) is visible.
- **T25.TA4 Behaviour unchanged.** Show a hidden panel from the menu (menu stays open, T25.AC6), "No hidden panels.", Esc, outside click, second click, focus return, `aria-expanded`: existing tests stay green; only position assertions are edited.
- **T25.TA5 Nothing left behind.** After close the popover is removed or hidden; `resize` while closed changes nothing (no leaked listener).
- **T25.TA6 CSS.** No hex outside `:root` in the diff of `board.css` (TU.9); no `position:fixed` left in `.pop` or `.cpop`.
- **Tests:** extend `test_squadboard_panels.py` (browser tests; check `grep -n "pop\|cpop\|Columns" tests/test_squadboard_*.py` first). Grep rule (TC.11): `grep -rl "board.css\|togglePop\|openColumns\|placeColumns\|\.pop\|cpop" tests/` and run every hit.
- **T25.TA6 Two more cases in TA2 (QA whitebox).** (a) Open the list while the page is already scrolled 600 px: AC1 holds. (b) Change the text size while it is open: still within 4 px of the button.
- **T25.TA7 Not clipped.** The Columns popover lives inside the panel header; an absolute popover is cut by a panel with `overflow:hidden/auto`. Test: Tasks panel with 1 row and a short `max_height`, open Columns: the popover is fully visible (compare its rect to the window, not to the panel).
