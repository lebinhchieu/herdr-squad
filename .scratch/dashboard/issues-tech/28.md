## Design notes
One function owns the rule, in `bin/squadtickets.py`:
```
scope_tasks(scope_home, repo_root=None, name=None) -> {"tasks": [{"id": "01", "title": "...", "status": "done", "where": "<repo-relative posix path>", "abs": "<resolved path>"}],
                                            "source": "declared" | "scope" | "scratch" | None, "dir": "<repo-relative folder>" | None}
```
Sources, in the Manager's plan order (`iterations/2.md`); first one that has at least one ticket file wins; **no merging, no scoring, no other scope's folder**:
1. `scope.md` line `tickets: <slug>` → `<repo>/.scratch/<slug>/issues/NN-*.md`. If the line is present it is the only source (folder missing or empty → `source: None`, shown as unknown, not a fall-through).
2. else `<repo>/.scratch/<scope name>/issues/NN-*.md` (direct children whose name starts with digits and a dash; a folder like `03-x/` is not a ticket).
3. else the scope's own files `<scope home>/tasks/NN.md` or `NN-*.md` (digits first; no subfolders, so `tasks/issues/` drafts and `brief-*.md` do not count). This is the `accounts/cswitch-bg` case: its `.scratch/cswitch-bg/issues/` holds only an evidence folder, so source 2 is empty and 3 answers.
`repo` = nearest parent holding `.scratch` or `.claude` (as `squadboard_tasks._repo_of`); `repo_root` argument wins when given. `name` = the scope name, passed in by the caller (`c.name` in the report, the scope folder name in the board); the function never reads it from the folder, because `test_squadtickets.py` has folder `x` and name `feat`. The order lives in one tuple, so a BA change of order is one line. Plan order is also the safe one: FILE-11 has roles draft tickets in `$SCOPE_DIR/tasks/`, so a mid-commit scope would otherwise list its drafts first. (BA: confirm in 28's Rules.)

- `find_tickets(c, raw_tokens)` stays as a thin adapter over `scope_tasks` (same signature, returns `({NN: title}, dir)`; `raw_tokens` unused, documented). `squadboard_tasks._ticket_folder` and `squadboard_list._tickets` call `scope_tasks` too; their own copies are deleted. The "equal to list" test becomes "all three call `scope_tasks`".
- Helpers in the same file, shared: `title_of(text, nn)` (first `# ` heading; strip a leading number only when it equals `nn`, with an optional separator `:` `.` `-` or a space; fallback = file stem without the number) and `status_of(text)` (first 12 lines, `Status:` value, lowercase, **first word only**: `done (Manager-confirmed...)` → `done`; `ready-for-agent` stays).
- Row shape (additive, `schema_version` unchanged): task rows from `/api/tasks` gain `where` (repo-relative display path), `abs` (resolved path, only when under the squad folder or `<repo>/.scratch`, else omitted), `ticket_status` (the word). Existing fields untouched. `list` gets its x-of-y done from the same `status`.
- Panel (`panel_tasks.js`): a column `Where` (id `where`, label "Where it lives") added **at the end and shown by default**; the title cell keeps the title. `where` is text (a click opening it is ticket 30's helper; 28 shows text only). The saved columns of ticket 20 must load without it (additive: a saved list missing `where` appends it at its default place). The empty text stays only when `source` is None: "No tasks yet. ..." unchanged; with `tickets:` declared but missing add "scope.md names `.scratch/<slug>` but it is not there".
- Reader still never raises; unreadable file = title from the name; CRLF ok; a symlinked ticket file whose target is outside the roots is listed without `abs`.
