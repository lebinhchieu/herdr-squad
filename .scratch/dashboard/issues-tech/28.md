## Design notes
One function owns the rule, in `bin/squadtickets.py`:
```
scope_tasks(scope_home, repo_root=None, name=None) -> {"tasks": [{"id": "01", "title": "...", "status": "done", "where": "<repo-relative posix path>", "abs": "<resolved path>"}],
                                            "source": "declared" | "scratch" | "scope" | "plan" | None, "dir": "<repo-relative folder or plan file>" | None,
                                            "looked": ["<repo-relative folder or file tried, in order>"]}
```
Sources, in the Manager's plan order (`iterations/2.md`); first one that has at least one ticket file wins; **no merging, no scoring, no other scope's folder**:
1. `scope.md` line `tickets: <slug>` → `<repo>/.scratch/<slug>/issues/NN-*.md`. Folder missing or with no ticket file → **falls through** to 2, 3, 4 (BA T28.AC12; this replaces my first design, which stopped).
2. else `<repo>/.scratch/<scope name>/issues/NN-*.md` (direct children whose name starts with digits and a dash; a folder like `03-x/` is not a ticket).
3. else the scope's own files `<scope home>/tasks/NN.md` or `NN-*.md`, **and** `<scope home>/tasks/issues/NN-*.md` (drafts before the Dev commits them; BA T28.AC14: this scope's 01-30). Digits first; a folder `NN-x/` is not a ticket; `brief-*.md`, `TEMPLATE.md`, `*.coach.md`, `*.summary.md`, `issues-tech/` do not count. If a number is in both places, `tasks/NN*.md` wins. This is the `accounts/cswitch-bg` case: `.scratch/cswitch-bg/issues/` holds only an evidence folder, so 2 is empty and 3 answers.
4. else a plan table: the first of `<scope home>/plan.md`, `<scope home>/tasks/plan.md`, or the iteration plan the scope names (`iterations/<n>.md`, newest) that has table rows whose first cell is a task id (`NN`, digits only). Row = id from cell 1, title from cell 2 (markdown stripped), `where` = `plan table, <file name>`, no `abs`, `ticket_status` empty (stage `todo` unless the ledger says more). `source: "plan"`.
`repo` = nearest parent holding `.scratch` or `.claude` (as `squadboard_tasks._repo_of`); `repo_root` argument wins when given. `name` = the scope name, passed in by the caller (`c.name` in the report, the scope folder name in the board); the function never reads it from the folder, because `test_squadtickets.py` has folder `x` and name `feat`. The order lives in one tuple, so a BA change of order is one line. Plan order is also the safe one: FILE-11 has roles draft tickets in `$SCOPE_DIR/tasks/`, so a mid-commit scope would otherwise list its drafts first. (BA confirmed this order in 28's Rules, 2026-11-04. Where my text and the BA ticket differ, the BA ticket wins: business behaviour.)

- `find_tickets(c, raw_tokens)` stays as a thin adapter over `scope_tasks` (same signature, returns `({NN: title}, dir)`; `raw_tokens` unused, documented). `squadboard_tasks._ticket_folder` and `squadboard_list._tickets` call `scope_tasks` too; their own copies are deleted. The "equal to list" test becomes "all three call `scope_tasks`".
- Helpers in the same file, shared: `title_of(text, nn)` (first `# ` heading; strip a leading number only when it equals `nn`, with an optional separator `:` `.` `-` or a space; fallback = file stem without the number) and `status_of(text)` (first 12 lines, `Status:` value, lowercase, **first words**: `done (Manager-confirmed...)` → `done`; `handed in e8a7c5f, ...` → `handed in`; `in progress` stays two words; `blocked`; anything else, e.g. `ready-for-agent`, kept as its first token). The stage mapping is the BA table in ticket 28 Rules (ledger words of ticket 07 win; `handed in` = checking if the ledger has a HANDIN, else in progress; others todo).
- Row shape (additive, `schema_version` unchanged): task rows from `/api/tasks` gain `where` (repo-relative display path), `abs` (resolved path, only when under the squad folder or `<repo>/.scratch`, else omitted), `ticket_status` (the word). Existing fields untouched. `list` gets its x-of-y done from the same `status`.
- Panel (`panel_tasks.js`): a column `Where` (id `where`, label "Where it lives") added **at the end and shown by default**; the title cell keeps the title. `where` is text (a click opening it is ticket 30's helper; 28 shows text only). The saved columns of ticket 20 must load without it (additive: a saved list missing `where` appends it at its default place). Empty text when `source` is None: **"No task files found. Looked in: <looked, comma separated>."** (BA T28.AC7; never the "Manager has not published" wording). The `looked` list is the folders and plan files of sources 1-4 that were tried, repo-relative; the needs-you count is unchanged. Plan rows show `plan table, <file>` as Where, as plain text.
- Reader still never raises; unreadable file = title from the name; CRLF ok; a symlinked ticket file whose target is outside the roots is listed without `abs`.
