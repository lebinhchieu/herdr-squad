# Technical AC 26: layout by column (Tech Lead: board-tl-dashboard)
Common AC that apply: TC.1, TC.3, TC.6, TC.10-TC.12; UI-COMMON TU.1-TU.5, TU.9. **Starts only after `ui-design/design-v7.md` is `Status: final`** (LC-2b). Binding with the BA's `tasks/issues/26-*.md` and the Designer's v7 (the look and the drag feel are theirs; this file is structure and safety).

## Design notes
- Today `layout.pack` places each panel at "the lowest then leftmost free cell" in a 12-wide grid with dense fill: panels flow along rows, a panel jumps to wherever a hole is. The PO says: arrange by column. Meaning for the data: the page has N columns; each column is a stack read top to bottom; a panel belongs to one column; the next panel goes to the end of a column, not into a hole of the row above.
- State: `board-ui.json` per panel is `{order, span, hidden, max_height}` (architecture §1a says "no pixel x/y, no row index"). Column stacking needs which column. **If design-v7 lets the PO choose a panel's column** (drag across columns), the smallest change is an **optional additive** `col`; **if v7 fills the columns from `order` alone, no `col`, no server change and no deviation: drop everything below about `col`** (I read v7 before the Dev starts and mark which case holds in the ticket). The `col` case: an **optional additive** `col` (0-based column index) in the panel state. A column index is not a pixel or a row, so §1a's intent holds, but its sentence "stores per panel: order, column span, hidden, max-height" gains one item: **this is a written deviation from architecture.md (SIZE-23d); the Architect is out, so the Manager decides it (MSG-20, CORE-4): I send the Manager a `DECISION`-request and write the decision into `tasks/decisions-iter2.md` before the Dev starts (MSG-14); then the ADR 0020 amendment in `promote.md` (31) repeats it.** Reading rule: a saved layout without `col` (every layout saved today) is valid; its columns are derived from `order` by the same auto rule (fill the shortest column in order). `version` of the file is not bumped (additive).
- Code: `layout.js` only for the rule. `pack(panels, n, unit)` keeps its signature and result shape `[{id, col, row, span, rowSpan, scroll}]` so `mount` and the other callers do not change. New pure helper `columnize(panels, n)` -> `{id: col}` (the auto rule, no DOM). `pack` then stacks: for each column, panels in `order`, `row` = sum of heights above. `autoPlan` keeps its job (least empty area on a new choice, font change, show/hide) but evaluates column stacks (it tries the permutations of `rest`; keep the cap: at most 7 visible panels, so 720 perms x width combos: measure it, keep under 50 ms; if over, limit width combos). Span rule: a panel spanning k of the n columns occupies k adjacent columns and sits at the max bottom of those columns; this keeps today's "Work time is wide".
- Drag (DOM part of `layout.js`, `mount`): dropping a panel onto a column's position sets its `col` and `order`; the ghost shows the target column. Keyboard moves (the existing key handlers) get left/right to change column; up/down reorder as today. Design v7 says how it looks.
- `resetLayout` (board.js) sets `S.auto = true` and clears `col`; `board.js` is touched only to pass `col` through `get()`/`set()` and in the save snapshot. `bin/squadboard_ui.py` (server, `_clean` ~l.96-110) **whitelists the panel keys and rebuilds each row as `{order, span, hidden, max_height}`: it silently drops `col`** (verified, read). So 26 also edits `bin/squadboard_ui.py`: accept `col` (integer 0..11, optional) and keep it in the clean row; `NO_POSITION_KEYS` (`x y row`) does not forbid it. Without this the columns would not survive a reload.

## Technical AC
- **T26.TA1 Pure.** `BOARD.layout.pack` and `columnize` touch no DOM/window/clock (TU.1). Test calls them in headless Chrome `--dump-dom` as today.
- **T26.TA2 Column stacks (the PO's case).** 4 panels of different heights, n=3 columns: each column's panels have `row` = sum of the heights above them; no panel overlaps another; the next panel in order goes to the column the rule names (design v7 table of the rule is copied into the test as the expected values). One test per width (`cols` 12 and 8).
- **T26.TA3 No dead gap kept.** The old guarantee (ticket 10: PO's short-next-to-tall case at 3 font sizes, 1/3/8-row panels) still holds: bottoms of the columns differ by at most one panel row unit, or the Designer's rule says otherwise. The existing no-dead-gap tests are updated to the column rule where they pinned row-first placement; the HANDIN lists each edited test.
- **T26.TA4 Old saved layouts load.** A `board-ui.json` fixture saved before this ticket (no `col`) renders, in the same order, with no error and no write on load. A layout with `col` out of range (`col: 9` for 3 columns) is clamped, not thrown. Two tests.
- **T26.TA5 Save round-trip.** Drag/keyboard move sets `col`; the `PUT /api/ui` body carries it; reload restores the same columns. The server accepts `col` (integer 0..11) and still refuses a non-integer (test in `test_squadboard_ui.py`). No other new key.
- **T26.TA6 Reset.** `Reset layout` returns to the auto rule and drops `col`.
- **T26.TA7 Width change.** Resizing the window across 1200 px (12 → 8 columns) re-derives columns without losing order; `col` is stored in the saved state as chosen, but the page uses `min(col, n-1)` (no write on resize).
- **T26.TA8 Cost.** `autoPlan` with all panels visible takes under 50 ms in the test page (measured and printed in evidence), never run on a data refresh (as today).
- **T26.TA9 Docs.** `architecture.md` is not edited by this ticket (Architect's file); the deviation is recorded in `promote.md`.
- **Tests:** extend `test_squadboard_page.py` (pack tests live there), `test_squadboard_ui.py` (col key), the layout part of `test_squadboard_panels.py` only if it pins placement. Grep rule (TC.11): `grep -rl "layout\|pack(" tests/` and run every hit.
