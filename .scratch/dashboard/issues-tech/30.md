# Technical AC 30: a file click opens VS Code (Tech Lead: board-tl-dashboard)
Common AC that apply: TC.1, TC.3, TC.6, TC.10-TC.12; UI-COMMON TU.3, TU.4, TU.5, TU.6. Binding with the BA's `tasks/issues/30-*.md`. Blocked by 29 (same file `squadboard_files.py`).

## Design notes
- The click code is in `templates/board/panel_files.js` (lines ~177-215: `link.target = "_blank"`, a markdown preview that calls `root.open("", "_blank")`). Not in `board.js`.
- Link = `vscode://file/<absolute path>` (URL form: `vscode://file/home/me/x.md`; Windows: `vscode://file/C:/Users/x.md`; optional `:line:col` not used). Build it with `encodeURIComponent` on each path segment, joined by `/` (so spaces, `#`, `?`, `:` and unicode survive); on a Windows path the drive letter segment (`C:`) keeps its colon.
- The page does not know the repo root, so the row carries `abs`: `squadboard_files._Walk.add` adds `"abs": str(real)` (real = the already resolved path inside the roots). Additive field, `schema_version` unchanged. `/api/file` stays as is (still serves; the page just stops linking to it from Files). The markdown preview and the sandboxed HTML tab go; their test pins change on purpose.
- A link to `vscode://` is a navigation to a custom scheme from a normal `<a href>`: no `target`, no `window.open`. `rel="noopener noreferrer"` kept. Local-only: absolute paths of the PO's own machine appear in `/api/files`, served on 127.0.0.1 with the Host check (TU, ADR 0020); named in the ADR note (promote.md).
- If VS Code is not installed the browser does nothing visible. Keep an always-visible fallback: title tooltip "Opens in VS Code" and a `copy path` button? Smallest honest fix: the link `title` says "Opens in VS Code. Path: <abs>" so the PO can copy it. The BA decides if a copy button is wanted (business AC); I only require the tooltip with the full path.
- `vscodeUrl(abs, distro)` is a pure function exported on `BOARD` and defined in `panel_files.js` (not `board.js`; TU.1: callable without events). **30 does not touch `panel_tasks.js`** (28 edits it in parallel). Making the Tasks `where` text a link is a follow-up after 28 merges, only if the PO asks.

## OPEN: WSL (raised to the Manager and BA, MSG-15, before 30 starts)
This board runs on WSL2 (`WSL_DISTRO_NAME=Debian` here). If the PO's browser and VS Code are on the Windows side, `vscode://file/home/chieule/x.md` is read as a Windows path and opens nothing; the form for a WSL file is `vscode://vscode-remote/wsl+<distro>/<abs path>` (**to verify by hand with one link of each form: nobody has yet**). Design that works for both: the server adds `wsl_distro` (value of `WSL_DISTRO_NAME`, or `null`) next to the rows in `/api/files` data (additive); `vscodeUrl(abs, distro)` returns the `vscode-remote/wsl+` form when `distro` is set, else `vscode://file/`. The BA/PO must say which machine opens the link (Windows VS Code or WSL-side VS Code); the default I build is the WSL form when `distro` is set. A wrong default = a click that does nothing, so QA blackbox checks it on the PO's real setup.

## Technical AC
- **T30.TA1 URL function.** `BOARD.vscodeUrl(abs, distro)` (pure) returns `vscode://file/` + encoded path, or with `distro` `vscode://vscode-remote/wsl+<distro>` + encoded path. Tests: `/home/me/a b#c.md` → `vscode://file/home/me/a%20b%23c.md`; with distro `Debian` → `vscode://vscode-remote/wsl+Debian/home/me/a%20b%23c.md`; `C:\Users\me\x.md` → `vscode://file/C:/Users/me/x.md`; empty/undefined → `null` (no link). One test, four cases.
- **T30.TA2 The click goes nowhere else.** No row link in the Files panel has `target="_blank"` or an `/api/file` href; `grep -n "_blank\|root.open" templates/board/panel_files.js` has no hit. The `dataset.md` preview branch is deleted, not hidden. Test: render rows, assert `href` starts with `vscode://file/` for md, html, json, and a `.scratch` file.
- **T30.TA3 Row carries `abs`; data carries `wsl_distro`.** `squadboard_files` rows have `abs`, data has `wsl_distro` (str or null, from the env; test sets and unsets it), equal to the resolved path, always inside the roots (symlink out → row not listed, as today). Test in `test_squadboard_files.py`.
- **T30.TA4 Untrusted text is text (TU.3).** A file name with `<img onerror>` shows as text; the `href` is set by property, never `innerHTML`. No `javascript:` can result: `vscodeUrl` always starts with the fixed prefix (test: abs `javascript:alert(1)` gives `vscode://file/javascript%3Aalert(1)`, not a script URL).
- **T30.TA5 Tooltip.** Link `title` contains the absolute path (so a PO without VS Code can copy it).
- **T30.TA6 Old pins changed on purpose.** `tests/test_squadboard_panels.py` ~674 and any test reading `Opens in a new tab` / `dataset.md` are rewritten to the new rule; the HANDIN lists each. None skipped.
- **T30.TA7 Live check (REV-5b).** QA whitebox reads the rendered `href` in headless Chrome `--dump-dom` for a real row; clicking VS Code is QA blackbox's manual check on a machine that has VS Code (evidence: a note, not a screenshot of VS Code).
- **Tests:** `test_squadboard_panels.py` (Files part), `test_squadboard_files.py`. Grep rule (TC.11): `grep -rl "panel_files\|_blank\|api/file" tests/`; run every hit (server tests of `/api/file` must stay green: the route is unchanged).
