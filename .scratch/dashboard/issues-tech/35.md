## Design notes
- **Mechanism (D6 revised after the BA's AC: "stable on refresh", "no gaps down a column", "first free spot"):** the page places panels with a **pure packer** `pack(items, n)`, `items = [{id, span, h}]` in reading order, `n` = grid columns -> `{id: {col, top}}`. Skyline rule = the BA's rule: keep the bottom of each grid column; a panel of span `s` goes to the start column `c` (0..n-s) with the smallest top = `max(bottom[c..c+s-1])`, ties leftmost; its bottom = top + h + 12 (gutter) in all its columns. So a later narrow panel lands in the lowest free space beside a tall one (fills the hole), and a panel's top is the bottom of the lowest panel above it plus 12 px. Nothing overlaps by construction. CSS: `#canvas` is a grid, `grid-template-columns: repeat(var(--n), minmax(0,1fr))`, `column-gap: 12px`, `grid-auto-rows: 1px`, `row-gap: 0`; each panel gets explicit `grid-column: c+1 / span s` and `grid-row: top+1 / span h` (px as rows; the 12 px gutter is added to `h` in the packer, panel has `margin-bottom` 12 px inside its area). 2 px tolerance of the AC holds (integer px).
- **Stable on refresh (T35.AC10):** placement runs only at placement moments: first settled load (after the first data of every shown panel), a PO action (drag, hide, show, Reset, Fit, height resize, width resize of 36), a change of window width (n) or text size. At a placement moment each panel's height `h` is measured (content, capped by `max_height`) and **frozen** as an inline `height` until the next placement moment. A 5 s refresh only fills the panel body (it scrolls inside if the content grew); it never calls `pack`, so no panel moves. `Fit` re-measures. Cost: a panel whose content grows after load shows a scrollbar until Fit or the next placement: say it in design-v8.
- **Rejected:** (a) CSS `grid-auto-flow: dense` with live row spans: a refresh changes heights, so panels jump (breaks AC10). (b) the shortest-column packer of 26 with spans: a wide panel cannot span columns. (c) CSS `masonry`: not shipped. (d) absolute pixel positions: breaks text scale and Tab order.
- **Reading order = `order`.** The grid places panels in `order` (dense may show a later panel earlier on screen; the DOM order and Tab order follow `order`). `col` is dropped from the model. Track count `n` = `colCount(innerWidth, scale)` as today unless v8 changes the thresholds (v8 decides: 1 / 2 / 3 or more tracks).
- **Migration of saved layouts (D5):** a panel row with `col` is an old layout (a row with only an old `span`, as in iteration 1, is also treated as old: its `span` is ignored): new order = sort all shown panels by (`order`, `col`, default rank) and renumber 0..k-1; `col` is not written again (the next save drops it); `max_height` and `hidden` stay. A file with no `col` at all keeps its `order`. The server is unchanged and keeps accepting `col` (old PUT, old file). The pure function `migrate(panels)` does it; tests call it.
- **Drag:** header drag as today (4 px, Esc cancels). The drop spot is found by `dropIndex(rects, x, y)` (pure): the index of the panel whose box centre is nearest to the pointer in reading order (before it when the pointer is above/left of the centre). The ghost has the dragged panel's span and height. A drop outside the canvas cancels. Saves `order` for every shown panel (renumbered).
- **Keyboard (kept from 26):** a focused panel title: Left/Up move the panel one place earlier in `order`, Right/Down one later; Shift+Up/Down change the height by 80 px (unchanged); focus stays on the title.
- Hidden panels keep their `order`; showing one puts it at its saved order (a new panel with none goes last).
- Pure functions on `BOARD.layout` (TU.1): `colCount`, `pack(items, n)`, `migrate(panels)`, `dropIndex(rects, x, y)`, `norm(panels)` (display order, hidden skipped). No DOM, window or clock inside them.
