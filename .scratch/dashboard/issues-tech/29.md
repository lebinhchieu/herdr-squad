# Technical AC 29: Files shows the `.scratch` dir and the squad dir (Tech Lead: board-tl-dashboard)
Common AC that apply: TC.1-TC.12 (TC.2 read-only: listing only). Binding with the BA's `tasks/issues/29-*.md`. Conforms to `architecture.md` §1 (file allow-list: squad folder and `<repo>/.scratch` only) and §6 M8.

## Design notes
- Today `list_files` lists named subfolders only (`tasks/`, `ui-design/`, `evidence/`, report, ticket `evidence.md`). The PO wants to see the two folders themselves: the squad dir (`.claude/squads/<squad>`) and the scope's `.scratch` dir (`<repo>/.scratch/<scope or tickets: slug>`). Add rows for what lives there that is not listed yet, using the existing `_Walk.files(...)` (depth 3, `MAX_ROWS` 500, no symlinked folders followed, `_under` check in `add`). Exact file set, kinds and names are the BA's (ticket 29 Rules); new `kind` values only by adding to `KINDS` and `WHAT` (additive). Row shape unchanged: `{name, kind, what, scope, path, mtime}`.
- Scratch folder = the one `squadtickets.scope_tasks(...)["dir"]` returns (ticket 28), so Files and Tasks name the same folder; with `source: None` no scratch rows, no error. This is why 29 runs **after** 28's `scope_tasks` exists, or the Dev of 29 calls the existing `declared_folder` / name rule and swaps in 28's function at merge (Manager's call; I advise: 29 starts on the current rule, a one-line change after 28 lands, since 29 touches only `squadboard_files.py`).
- Do not list: `messages.jsonl`, `inbox.jsonl`, `roles/`, locks, `_runtime`, ADRs (architecture §2a, ticket 14). A `.scratch` folder can hold large evidence images: list names and mtimes only, never open a file; `MAX_ROWS` cap and `truncated: true` already cover size.
- The two dirs are shown as rows or a group header: Designer/BA decide the look; data side stays a flat `rows` list (the page groups on `name` prefix or a new additive `group` field, BA's call).
