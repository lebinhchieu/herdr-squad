Iteration 3. Business AC: BA ticket `tasks/issues/36-*.md`. Design: `ui-design/design-v8.md` (handle look, hit area, snapping, narrow window). Common AC as 35. **Serial after 35** (same files).
Touches: `templates/board/layout.js` (resize east edge, `snapTracks`), `templates/board/board.js` (read/write `tracks` in the state, one place), `templates/board/board.css` (`.rz.e`, width rule), `bin/squadboard_ui.py` (`tracks` key in PUT), tests: `tests/test_squadboard_grid.py` (end of file), `tests/test_squadboard_ui.py` (`tracks` bounds).

## Design notes
- **State (D8):** the saved row gets **`tracks`** (integer 1..`TRACKS_MAX`=12, default 1; a row without it = default 1), NOT `span`: `span` already exists in iteration-1 files with an older meaning (`layout-26/board-ui-iter1.json`: 4, 8, 6) and an old `span` must never widen a panel (T35.AC8). `span` stays accepted by the server and ignored by the page. Stored as a number of tracks, never pixels. The page uses `min(tracks, n)` at draw time and does NOT rewrite a larger saved span when the window is narrow (like `col` above n-1 in 26), so a wide layout comes back when the window grows.
- **Server:** `squadboard_ui.py` PUT accepts `tracks` int 1..12 (same error shape as a bad `order`), keeps accepting `span` and `col`. **Reading:** `read_state` hands rows back as saved, so a bad value (0, -2, "wide", 99; T36.AC9) reaches the page: the page's own reader makes it safe: not an int >= 1 -> default 1 (0, -2, text); above 12 or above n -> clamped (99 -> min(12, n)). No error text. The file is not rewritten by reading. Version stays 1; no new key; old files read as 1 track.
- **Resize:** east-edge handle `.rz.e` (a sibling of `.rz.s`); `snapTracks(px, trackW, gap, n)` (pure) = nearest integer 1..n of `(px + gap) / (trackW + gap)`. During the drag the panel shows the snapped width live (`grid-column: span k` set on each change of k, not each pixel); pointerup saves; Esc restores. Keyboard (BA T36.AC10): the handle is a focusable element (Tab); Left / Right on it make the panel one track narrower / wider; focus stays on the handle; at 1 and n nothing changes. design-v8 may change the keys.
- **Neighbours reflow by themselves** (dense grid, ticket 35): nothing else is edited. Growing a panel past the last track is clamped to n; with n = 1 the handle is hidden.
- Panel inner tables use `overflow:auto` already; a narrower span must not clip the header buttons (design-v8 decides the minimum width; one track is the floor).

## Technical AC
- **T36.TA1 `snapTracks`.** Table: exact track edges, half-way up and down, below one track -> 1, beyond n -> n, n = 1 -> 1.
- **T36.TA2 Save and load.** A resize drag in the harness ends with `opts.set(id, {tracks: k})` and one `opts.changed`; the PUT body row has `tracks: k` and no `col`; reload with that file draws the panel k tracks wide at the window size named by the AC (geometry: width = k tracks + (k-1) gaps).
- **T36.TA3 Narrow keeps the saved span.** Saved `tracks` 3 at n = 3 draws 3 wide; at n = 2 it draws 2 wide; back to n = 3 draws 3 again, and the saved value was never rewritten (compare the state, not only the pixels).
- **T36.TA4 Server bounds and bad saved values.** `PUT /api/ui` with `tracks` 0, 13, "2", 2.5 or true is refused with the same error shape as a bad `order`; 1 and 12 are kept. Old body without `tracks`, and one with an old `span`, is accepted. Page reader (T36.AC9): a file with `tracks` 0, -2, "wide", 99 on four panels opens with no error text; they draw at 1, 1, 1 and min(12, n); an iteration-1 `span` is ignored.
- **T36.TA5 Esc and keyboard.** Esc during the drag restores the old width and saves nothing; Right on the focused handle adds one track and stops at n, Left stops at 1; focus stays on the handle.
- **T36.TA6 Holes still fill and neighbours re-place once.** A width change is a placement moment (T35): `pack` runs once on pointerup, not on every pointer move (the live outline is a separate element, no re-place while dragging, T36.AC4). After a widening the geometry check of T35.TA2 still holds (no overlap; a short panel fills the freed hole).
- **T36.TA7 Handle structure.** The handle has a role and an accessible name (`Resize width`), its hit area is the one in design-v8 (QA blackbox measures it, REV-18b); whitebox checks only that the element exists and is a keyboard peer.
- **Tests:** as 35. Grep rule (TC.11): `grep -rl "squadboard_ui\|span\|layout.js" tests/`; run every hit.
