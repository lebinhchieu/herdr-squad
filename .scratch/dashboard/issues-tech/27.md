# Technical AC 27: Work time filter block restyle (Tech Lead: board-tl-dashboard)
Common AC that apply: TC.3, TC.6, TC.10-TC.12; UI-COMMON TU.3, TU.4, TU.9. **Starts after `ui-design/design-v7.md` is `Status: final`.** Binding with the BA's `tasks/issues/27-*.md`. The look is the Designer's; this file is where and how.

## Design notes
- The block is `.tl-bar` and its rows `.tl-r`, built by `toolbar()` in `templates/board/timeline.js` (~665-700). Its CSS is the `CSS` array of the same file (~542-552), injected by the file itself. **Not `board.css`**, so 27 touches only `timeline.js` and cannot collide with 25/26.
- Cause (read): `.tl-bar{background:var(--bg);border-bottom...;padding:4px 0 5px}`: `--bg` is the page cream (`#FCF8F1`), which reads as white next to the panel colour `--panel`; padding is 0 left/right so chips touch the border.
- Fix = CSS values only, tokens only: background `var(--panel2)` or `var(--panel)` as v7 says, a 1px `var(--border)` all round, `border-radius:var(--r)`, padding ~`6px 10px`, a row gap that survives Extra large. `position:sticky;top:0;z-index:30` stays (the bar stays visible while the swimlanes scroll): the new background must be opaque so lanes do not show through. Chip and button rules (`.tc`, `.tl .seg`) keep their tokens; `.tc.on` stays ink on cream.
- No change to the toolbar's DOM, ids, `dataset.preset`, or handlers: the existing timeline tests select by those.

## Technical AC

- **T27.TA3 Text never touches the border.** For every chip/button in the bar: its left edge minus the bar's left padding edge >= 8 px (first in row), right likewise (last in row), at a 1000 px wide window where the rows wrap. One test.

- **T27.TA5 No behaviour change.** The existing timeline tests (preset buttons, task chips, zoom, pan, gap select) pass unedited. The DOM of `toolbar()` is the same (class names added only). `git diff` of `timeline.js` shows only the `CSS` array (and at most class names in `toolbar()`).
