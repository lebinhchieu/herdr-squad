Squad board: user guide

Start it: /squad:squad-board in a herdr pane, then open the URL it prints. It also opens by itself with /squad:squad-start.

Read it top down: the orange bar is what waits on you, a red hatched bar is an agent blocked, a yellow hatched bar is an agent waiting on a background job.

1. What does each part of the board mean?

Space

Time runs downward, one column per agent. Hover a pin (or its note) and the other lights up.

  1. Needs-you bar: what waits on you. A blocked agent, an unanswered escalation, or an idle Manager with an empty PO check-in; else “Nothing is waiting on you”. Enable alerts: each new item then rings a chime and a notification, and the tab title shows (3) squad board. bin/squad-board:698 derive_needs_you · bin/squad-board.html:1353, 1425verified
  2. Iteration picker: look at an earlier round. The newest iteration is live. An older one shows a “Replay of iteration N” banner and stops following; ↓ live comes back. bin/squad-board.html:1023, 975verified
  3. Header card: one per rostered agent. Dot = status. ⏱ teal = working total (blocked time included), ⛔ red = blocked total, right number = context tokens. Red outline = blocked; orange = panel open. Click it for the panel (below). bin/squad-board.html:324, 431-474verified
  4. Teal bar: the agent was working. It starts where a message woke the agent, so cause and effect line up; it ends when the agent goes idle (◆ idle · 1m 20s is how long it ran). ⟲ on the left: nothing woke it (you typed to it). bin/squad-board.html:626 · bin/squad-board:464 cut_unrecordedverified

  6. Red hatched part: blocked in that stretch. The agent is also on the needs-you bar. A yellow hatched part means waiting on a background job (question 2). bin/squad-board.html:633verified
  7. “7 min quiet”: nothing happened here. A quiet stretch over 3 minutes between two rows folds into one line, so the page stays short. bin/squad-board:369 FOLD_GAP_S = 180verified

2. Which status is an agent in, and why?

State

Four statuses. The board takes working, blocked and idle from herdr, and adds one of its own: waiting. An agent is waiting when herdr calls it idle but the last line of its pane says a shell or a monitor still runs.

Not drawn: when a pane closes the board records done, which the page shows as idle (row 8).

What the recorder looks at: the last line of the pane

✓⏵⏵ auto mode on (shift+tab to cycle) · 1 shell still running
✓⏵⏵ auto mode on · 3 monitors
✗⏵⏵ auto mode on · ← 1 agent
✗⏵⏵ auto mode on (shift+tab to cycle)

Only the last non-empty line counts; the same words higher up in the conversation do nothing. ← N agents is in every herdr pane's footer, all the time, so it is not a signal and is ignored. The first design counted it and made every idle agent waiting for good.

The footer samples are real pane captures kept as test fixtures. The patterns are N shells still running and N monitors; the label on the bar says which one.

3. How do I start, restart and stop it, and what if it breaks?

Time

One command starts it, one flag restarts it, and closing its tab stops it. The steps below are in the order you meet them; the table on the right is for when one of them goes wrong.

  1. Be inside herdr, at the project root. The board needs Python 3, herdr, jq, git and HERDR_ENV=1 (set in every herdr pane). bin/squad-board-start:25-26 verified
  2. Start it: /squad:squad-board or squad-board-start [--squad NAME]. It runs bin/squad-board in a herdr tab labelled board, waits up to 10 s for the URL, and prints it. A second call finds the running tab and prints its URL: never a second board, one board per herdr workspace. /squad:squad-start does this on its own. bin/squad-board-start:57-67 · skills/squad-board/SKILL.md verified
  3. Note the port. 127.0.0.1 only, port 7420. Busy: it tries 7421 to 7440, and the printed URL shows the one it got. bin/squad-board:28-29, 1782 verified
  4. Open the full URL, token included. http://127.0.0.1:7420/?token=…. The token is needed for the three actions that do something: Jump to pane, notes.md and show more. Without it the page still draws. bin/squad-board.html:1064 verified
  5. Restart if the page will not load, the URL is lost, or the board died. /squad:squad-board restart or squad-board-start --restart: closes the old tab, starts a fresh board. bin/squad-board-start:47-50 verified
  6. Stop it. Close its herdr tab (the one labelled board), or press Ctrl-C in that tab. The board never changes your squad, so stopping is safe. inferred the stop path is a plain process exit; no stop command exists in the scripts.

Replay mode: look at a copy of a squad

cp -r .claude/squads/<squad> /tmp/squad-copy
bin/squad-board --replay /tmp/squad-copy \
  --now 2026-10-14T12:00:00Z --port 0

Replay serves a folder as it is: no recorder, no live pane status. --now fixes the clock (an ISO time with a zone) so a page can be reproduced; --port 0 lets the system pick a free port. Use a copy; the demo data is in tests/fixtures/board/. Without --replay the board needs a real squad folder (SQUAD_DIR, or <git root>/squad).

Two folder layouts

Per-scope (current): scopes/<scope>/ and goals/<goal>/ under the squad folder; the board reads every scope and goal and checks each scope's Manager against its own check-in. Flat (legacy): roster.md at the top, no scopes/.

If it breaks: problem → fix

ProblemWhy, and the fix
No agents on the boardThe columns come from roster.md. Check the agents are on it, and that you started the board for the right squad (--squad NAME if you have several). In a per-scope squad each scope has its own roster.
Page says “reconnecting…” or will not loadThe board process is gone or stuck. /squad:squad-board restart.
Board died, but the start command prints the same old URLKnown gap (BRD-21): a reused board tab whose board died still prints the old URL. Use --restart.
“ports 7420..7440 are all busy”Something else holds the range. Free a port, or run bin/squad-board --port N yourself.
“not inside a herdr pane”HERDR_ENV is not 1. Open herdr and run it from a pane there.
“Jump needs the token”You opened the page without ?token=…. Use the printed URL, or get it again with /squad:squad-board.
An agent shows idle when it is busyStatus comes from herdr. A shell or monitor started in the pane shows as waiting, not working. A long silent tool run records nothing while the recorder is down (question 4).
An agent shows waiting when it is notOnly the last pane line counts. If it still says N monitors, a monitor runs; stop it in that pane (question 2).
A bar looks far too longThe closing record was never written: the recorder runs only while the board runs. A bar no record backs is cut after 3 minutes of silence, but a recorded one can read hours long across a board restart (BRD-21). Treat it as unknown time, not work.
Bars are missing from before the board openedThey grow from when the recorder first ran; nothing is drawn for earlier time.
A needs-you item does not go awayBlocked clears when the agent works again. An escalation clears when its Answer cell in escalations.md is filled. The idle-Manager item clears when the PO check-in of the open iteration has text.
verified messages from bin/squad-board and bin/squad-board-start; needs-you rules at bin/squad-board:698; the long-bar and start-URL gaps from BRD-21.

4. Known limits, and what is not built

Short list

The recorder runs only while the board runs

The board writes the status records (activity.jsonl) itself. While it is down nothing is recorded, while messages.jsonl from the message hook keeps filling. Keep the board open while the squad works. verified

  • One board per herdr workspace.
  • Waiting sees only a shell or monitor in the pane's last line.
  • The board never changes your squad. Its only action, Jump, focuses a pane.
  • The logs hold message text; squad-init git-ignores them (*.jsonl).

Screen and test limits

  • 13 or more columns scroll sideways (each keeps at least 84 px) and the Tasks card leaves the view (BRD-26).
  • Pixel tests flake under load: test_board_sequence and others fail now and then when the machine is busy, and pass alone (BRD-21 items 19, 26).
  • Cosmetic: a waiting label can cross a neighbour's pill (BRD-21 item 23); a hand-made goal Manager has no idle check (no iteration file).
